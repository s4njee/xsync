# Installing xsync

## One-liner

```bash
curl -fsSL https://raw.githubusercontent.com/s4njee/xsync/main/scripts/install.sh | sh
```

Detects your platform, downloads the matching artifact, **verifies its checksum
before installing anything**, and places the binary in `~/.local/bin`. No root,
nothing written outside your home directory, and it tells you if that directory
is not on your `PATH`.

The script refuses to install if the checksum does not match, or if it cannot
fetch `SHA256SUMS` at all, and prints how to verify by hand instead. It does not
offer a flag to skip verification.

| Variable | Default | Meaning |
|---|---|---|
| `XSYNC_VERSION` | latest release | Version to install |
| `XSYNC_BIN_DIR` | `$HOME/.local/bin` | Where to install |

## Homebrew

```bash
brew install s4njee/tap/xsync
```

Covers macOS and Linux, both architectures. Installs the man page and bash, zsh,
and fish completions.

## Windows

```powershell
scoop install xsync
```

## Linux packages

`.deb` and `.rpm` are published with each release. They install to standard
locations — `/usr/bin/xs`, `/usr/share/man/man1/xs.1`, and the usual completion
directories — and declare `libc6 >= 2.28`, the glibc floor from
`docs/TARGET-MATRIX.md`, so installation fails cleanly on an older distribution
rather than the binary failing at runtime with a loader error that explains
nothing.

## From source

```bash
cargo install xsync
```

Requires a C toolchain, since compression is built from source.

## Manual

Download from the [releases page], verify against `SHA256SUMS` or the build
provenance attestation, and put `xs` anywhere on your `PATH`. See
[verifying-downloads.md](verifying-downloads.md) — worth reading if you download
through a browser on macOS or Windows, where Gatekeeper and SmartScreen behave
differently than they do for `curl`.

[releases page]: https://github.com/s4njee/xsync/releases

## What ships in an archive

```
xs                        the binary
man/xs.1                  man page
completions/xs.bash       bash
completions/_xs           zsh
completions/xs.fish       fish
completions/_xs.ps1       PowerShell
LICENSE-MIT
LICENSE-APACHE
README.md
```

The man page and completions are generated by the binary itself, from the same
parser that defines its flags, so they cannot document options it does not have.
You can regenerate them at any time:

```bash
xs --man > xs.1
xs --completions zsh > _xs
```
